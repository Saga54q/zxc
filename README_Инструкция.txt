2. КАК СОБРАТЬ ГОТОВУЮ БАЗУ ДАННЫХ «Поликлиника.accdb» (СПОСОБ 1 — В 1 КЛИК)
--------------------------------------------------------------------------------
  1. Распакуйте архив в любую папку на компьютере с ОС Windows и установленным
     пакетом Microsoft Access (2010 / 2013 / 2016 / 2019 / 2021 / Microsoft 365).
  2. Дважды щёлкните по файлу «Создать_БД_Поликлиника.vbs».
  3. Через 5–10 секунд в этой же папке появится полностью собранный файл
     «Поликлиника.accdb» со всеми 13 таблицами, схемой данных, тестовыми
     записями, 16 запросами, 7 формами, 4 отчётами, 6 макросами и ролями доступа.

3. КАК СОБРАТЬ БАЗУ ДАННЫХ ВРУЧНУЮ ИЗ MS ACCESS (СПОСОБ 2)
--------------------------------------------------------------------------------
  1. Создайте в MS Access пустую базу данных «Поликлиника.accdb».
  2. Нажмите Alt+F11 (откроется редактор Visual Basic for Applications).
  3. В меню «File -> Import File...» («Файл -> Импорт файла...») выберите файлы:
       VBA\ModSecurity.bas
       VBA\ModAdmin.bas
       VBA\AutoBuild.bas
  4. Нажмите Alt+F8, выберите макрос «СоздатьБД» и нажмите «Выполнить» (Run).

5. ЧАСТЫЕ ВОПРОСЫ И РЕШЕНИЕ ПРОБЛЕМ
--------------------------------------------------------------------------------
  Вопрос: при запуске скрипта появляется сообщение «Не удалось запустить
          Microsoft Access».
  Ответ:  проверьте, что установлен пакет Microsoft Access (не только Word и
          Excel) версии 2010 или новее. Скрипт использует объектную модель
          Access (Application.CreateForm / LoadFromText), которая появилась
          начиная с Access 2007/2010.

  Вопрос: скрипт сообщает, что файл «Поликлиника.accdb» занят.
  Ответ:  закройте базу данных в MS Access и запустите скрипт повторно.

  Вопрос: при сборке появилось сообщение о замечаниях (ошибках).
  Ответ:  сборщик ведёт журнал построения. Каждый объект создаётся независимо
          от остальных, поэтому одна ошибка не прерывает всю сборку. Полный
          журнал выводится в диалоговом окне и доступен в редакторе VBA
          (Alt+F11 -> Ctrl+G, окно Immediate). Повторный запуск процедуры
          «СоздатьБД» (Alt+F8) полностью пересоздаёт базу данных.

  Вопрос: при открытии готовой базы данных Access показывает жёлтую полосу
          безопасности «Предупреждение системы безопасности».
  Ответ:  нажмите «Включить содержимое» (Enable Content) — в базе используются
          макрос и программный код VBA.

  Примечание по имени вычисляемого поля запроса Q07_СтоимостьЛечения.
  В MS Access имя поля (Alias) не может содержать символы «.» и «,»: при
  создании запроса с именем вида «Сумма, руб.» возникает ошибка 3126
  «Недопустимое использование скобок». Поэтому вычисляемое поле названо
  «Сумма руб»; на оформление и итоги отчётов это не влияет.

6. ИСПРАВЛЕНИЯ В ТЕКУЩЕЙ ВЕРСИИ КОДА
--------------------------------------------------------------------------------
  1) Условия на значение (ValidationRule). Конструкции вида
     In ("М";"Ж"), In ("Запланирован";"Проведён";…) и
     In ("Основной";"Сопутствующий";…) — это синтаксис *мастера подстановок*
     (точка с запятой между значениями), а не языка выражений ACE. Заменены на
     корректные выражения: "М" Or "Ж", "Запланирован" Or "Проведён" Or …,
     "Основной" Or "Сопутствующий" Or … . Теперь правила проверки полей
     таблиц «Пациенты», «ЗаписиНаПриём» и «Диагнозы» создаются без ошибок.

  2) Служебная функция доступа к базе в модуле AutoBuild переименована
     из DB() в Db(). Имена в VBA нечувствительны к регистру, поэтому
     имя процедуры DB совпадало с именами локальных переменных
     Dim db As DAO.Database в процедурах очистки и выполнения SQL —
     это потенциальная причина ошибки компиляции «Ambiguous name detected».

  3) Подчинённые формы «Ф_Назначения» и «Ф_Диагнозы» переведены с запросов
     Q13_НазначенияПриёма и Q12_ДиагнозыПриёма на таблицы «Назначения» и
     «Диагнозы». Запросы с соединением нескольких таблиц в MS Access не
     позволяют изменять данные, из-за чего подчинённые формы были доступны
     только для чтения. Теперь прямо в карте приёма можно добавлять услуги и
     диагнозы (кнопки «Добавить услугу», «Добавить диагноз») и удалять строки
     («Удалить строку»); все операции проверяют заполнение полей, диапазон
     количества (1–50) и записываются в журнал аудита ЖурналСобытий.

  4) Форма «Ф_ЗаписьНаПриём»:
     * номер талона формируется не только после выбора врача, но и при
       изменении даты и времени приёма (обработчики PropertyChanged);
     * добавлено скрытое поле КодРасписания: запись автоматически привязывается
       к соответствующему слоту расписания (функция DLookup), поэтому занятый
       талон отображается как занятый в запросах Q01 и Q11;
     * при попытке записать пациента на занятое время выводится предупреждение
       (двойной контроль: событие BeforeUpdate формы и уникальный индекс
       IX_Zap_Vrach_Time).

  5) Кнопочная форма «Ф_Главная»: добавлена фактическая проверка уровня
     доступа (функция ЕстьДоступ) при открытии форм и отчётов, отказы
     записываются в журнал аудита; кнопки недоступных операций блокируются.

  6) Повышена надёжность автоматического сборщика:
     * системные подтверждения удаления объектов отключаются на время сборки
       (DoCmd.SetWarnings False) и гарантированно включаются обратно;
     * высоты разделов форм и отчётов устанавливаются служебной процедурой
       ЗадатьВысоту — отсутствие раздела (заголовка/примечания) больше не
       прерывает создание объекта;
     * переименования временных форм и отчётов выполняются после проверки
       состояния объекта.

  7) Запрос Q01_СвободныеТалоны согласован с уникальным индексом
     IX_Zap_Vrach_Time: свободным считается только слот, на который нет ни
     одной записи. Ранее слот, освободившийся после отмены записи, выводился
     как свободный, хотя забронировать его было нельзя (индекс запрещает
     повтор времени у одного врача).

  8) В подчинённых формах включён контроль ввода (LimitToList) для списков
     услуг и кодов МКБ-10 — исключён ввод несуществующих значений.

  9) Для поля «КодМКБ» снята маска ввода «>L00.0»: коды МКБ-10 имеют разную
     длину (например, I10 и J06.9), и маска фиксированной структуры не
     допускала ввод кода I10. Вместо маски задано условие на значение
     Like "[A-Z][0-9][0-9]*" с поясняющим сообщением.

  10) Исправлены расхождения в документации: в README указан реально
      существующий логин врача-кардиолога dr_hairullina (было dr_karimov),
      уточнена формулировка о вычисляемом поле «Сумма руб».

  отчёт (Отчёт/Отчёт_Практика_АБД_Поликлиника_Сагадиев.docx) и архив комплекта
  «Практика_АБД_Вариант14_Поликлиника_Сагадиев.zip».
